# CoolERP Python SDK — local prototype for issue #60

This is a reviewable prototype, not a published or release-ready package. It
contains a typed sync/async SDK generated by Tungsten **0.1.3** from the actual
CoolERP router's OpenAPI 3.1 response. No production API was used.

## Source and isolation

- CoolERP baseline: `7944e3f248c4dabff53956af894472ea584158ca`.
- Tungsten tag `v0.1.3`, commit `9a8d60e6437fff409041caab4d3f8d87e067604e`.
- Runtime: published `tungsten-runtime` **0.1.3 from PyPI**. No source checkout,
  local runtime override, vendoring or direct-URL dependency is required.
- Python used: 3.12. Rust used: 1.99.0, explicitly pinned in Compose to avoid
  following CoolERP's floating `stable` toolchain.
- The SDK lives under `sdk/python`, with a small router OpenAPI exporter,
  Python CI, SQLx query metadata, and three Rust lockfile patch updates.
  No ledger or process-parser logic changed.
- Compose project `coolerp-sdk60-prototype` owns a disposable Postgres database
  on tmpfs using PostgreSQL 17. Its DB has no published port; API binds only host loopback port 38660.
  The test credentials are disposable constants, not production credentials.
- Exporter calls `/api-docs/openapi.json` through the real Axum router in process,
  using a lazy pool pointed at an unused loopback address. It performs no DB I/O.
  Compilation still needs a migrated disposable DB for existing SQLx macros.

## Reproduce (PowerShell, from repository root)

Prerequisites: Docker Desktop, Python >=3.12, and the reviewed, checksum-verified
Tungsten 0.1.3 executable for regeneration. Ordinary SDK installation needs only
Python and pip; it does not require the compiler or its source repository.

```powershell
$tungsten = '../tools/013/compiler/tungsten-0.1.3-x86_64-pc-windows-msvc/tungsten.exe'
& $tungsten --version
docker compose -f sdk/python/compose.yaml run --rm build
if ($LASTEXITCODE -ne 0) { throw 'OpenAPI export/build failed' }
& $tungsten generate sdk/python --strict
if ($LASTEXITCODE -ne 0) { throw 'Generation failed' }
& $tungsten generate sdk/python --strict --check
```

The build exports `sdk/python/openapi.json` and builds the API. Do not replace
the source contract with an invented schema or point generation at production.
`generated/` is generator-owned except its documented `custom/` extension point.
The outer package build applies the reviewed monetary overlay automatically;
see `MONEY_OVERLAY.md`. Never install the raw `generated/` directory directly.
The checked-in spec permits regeneration without Rust or a running server.

```powershell
python -m venv ../.venv-sdk-013-wheel
../.venv-sdk-013-wheel/Scripts/python -m pip --isolated install --no-cache-dir --index-url https://pypi.org/simple -c sdk/python/constraints-py312.txt ./sdk/python pytest
../.venv-sdk-013-wheel/Scripts/python -m pip check
../.venv-sdk-013-wheel/Scripts/python -m pytest sdk/python/tests/test_sdk.py sdk/python/tests/test_money_overlay.py -q
docker compose -f sdk/python/compose.yaml up -d api
if ($LASTEXITCODE -ne 0) { throw 'Disposable API failed to start; do not run tests' }
docker compose -f sdk/python/compose.yaml ps
$env:COOLERP_DISPOSABLE_TEST = '1'
try { ../.venv-sdk-013-wheel/Scripts/python -m pytest sdk/python/tests -q }
finally {
  Remove-Item Env:COOLERP_DISPOSABLE_TEST -ErrorAction SilentlyContinue
  docker compose -f sdk/python/compose.yaml down
}
```

Only opt in after confirming the above Compose API owns loopback port 38660.
No production/base-URL environment variable is accepted by integration tests.
`down` destroys the tmpfs ledger, retaining only project-specific build caches.
Tests compare balances before/after so they can run repeatedly without mutating
or deleting old ledger rows. Contract tests use `httpx.MockTransport`. Two transport regression tests also
check caller-thread callbacks and a native HTTPX deadline against an ephemeral
loopback server; that server has no ledger or database.

## Use integer cents

```python
from uuid import uuid4
from coolerp_sdk import CoolerpClient, Ok
from coolerp_sdk.custom.money import LedgerLine

# Only run this example against your disposable Compose instance.
with CoolerpClient(base_url="http://127.0.0.1:38660", validate_responses="strict") as sdk:
    key = str(uuid4())  # Persist this exact UUID and payload for a manual retry.
    posted = sdk.journal_entries.create(
        actor="sdk-disposable-test", journal_code="GEN", entry_date="2025-01-15",
        idempotency_key=key,
        lines=[LedgerLine(account_code="1000", debit=10000, credit=0),
               LedgerLine(account_code="4000", debit=0, credit=10000)],
    )
    assert isinstance(posted, Ok), posted
    balance = sdk.accounts.balance.get(code="1000")
    assert isinstance(balance, Ok), balance
    print(balance.value.balance)  # int, in cents
```

All 20 declared cents fields in the installed package's normal model classes
reject floats, booleans, Decimal, strings and values outside signed i64. The
build overlay also protects flattened process amounts and response parsing.
`LedgerLine` additionally rejects negative amounts and zero/double-sided lines.
It adds local defense in depth; the real server/database enforce entry balance.
Tests also verify exact round-trip serialization of `2**53 + 1` cents offline.

## Compatibility findings and limits

- All **17 operations** generate. That does not establish full API coverage:
  live SDK tests exercise journal posting and account balance only. Async
  posting/balance have offline transport coverage; other resources and async
  methods have not received live end-to-end testing.
- `TG0303`: `propertyNames` is ignored on `AdvanceInstanceRequest.amounts`.
  Here it only says keys are strings, but the diagnostic must remain visible.
- `TG0760`: unreachable `ListInstancesQuery` is pruned. Its endpoint query
  parameters are generated; the standalone model is not.
- `--strict` still permits informational diagnostics; it is not proof of
  complete schema support.
- Unmodified Tungsten `LineRequest` accepts `10000.0` and arbitrary-size Python
  ints. The reproducible outer build overlay closes this gap for all 20 declared
  CoolERP cents fields, including raw model/dictionary entry points. It preserves
  negative signed balances, optional/null fields and unrelated IDs/counts.
  The untouched generator snapshot retains the upstream limitation.
- UUIDs are typed/validated strings. CoolERP's key is a **JSON body field**.
  Tungsten's key helper uses headers; `CallOptions.idempotency_key` must not be
  mistaken for CoolERP's body key. `agent.yml` disables automatic mutation
  retries. Tests check the body UUID, no synthesized header, timeout/no retry,
  201 creation, 200 replay with identical entry ID, and 409 changed-payload reuse.
- Packaged sync/async clients default to strict response validation. Malformed
  cents in a successful response return Err; explicit warn/off remains an opt-out.
  Schema validation is not a full accounting invariant check. Inventory unit_cost
  remains a decimal string as its contract requires; opaque JSON context fields
  cannot be assumed to carry typed cents.
- Generated pyproject lacks project licensing metadata. The small outer
  `sdk/python/pyproject.toml` packages the same generated module with the SDK's
  existing `MIT OR Apache-2.0` declaration and existing license texts. Install
  **sdk/python**, not its raw generated subdirectory, for the proposed package.
  Tungsten README explicitly says API owners choose the generated output license;
  its separate Python runtime is Apache-2.0.

## PyPI installation

Published `tungsten-runtime` 0.1.3 resolves from PyPI in a clean environment.
The SDK and generation manifest require tungsten-runtime>=0.1.3,<0.2.0,
Python >=3.12, Pydantic >=2.10,<3 and HTTPX >=0.27,<1. Runtime 0.1.3 additionally depends on sniffio>=1.3.
`constraints-py312.txt` pins the tested Python 3.12 dependency set; it is not a
cross-platform universal lock. No source checkout, local runtime override,
vendored runtime or direct-URL runtime dependency is required. The SDK itself
remains an unpublished local wheel.

```powershell
# Use a development environment with the Python build tool installed:
python -m build sdk/python --outdir ../wheelhouse
# Use a NEW environment name if this directory already exists:
python -m venv ../.venv-sdk-013-wheel
../.venv-sdk-013-wheel/Scripts/python -m pip --isolated install --no-cache-dir --index-url https://pypi.org/simple -c sdk/python/constraints-py312.txt ../wheelhouse/coolerp_sdk-0.1.0.dev0-py3-none-any.whl pytest
../.venv-sdk-013-wheel/Scripts/python -m pip check
../.venv-sdk-013-wheel/Scripts/python -m pytest sdk/python/tests/test_sdk.py sdk/python/tests/test_money_overlay.py -q
```

Then run the disposable integration tests above with this interpreter. See
`PYPI_VALIDATION.json` and `VALIDATION.md` for index provenance and test evidence.
